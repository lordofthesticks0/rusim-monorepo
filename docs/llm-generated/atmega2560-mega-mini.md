# ATmega2560 Mega Mini — Development & Reference Documentation

## Overview

The **ATmega2560 Mega Mini** (also marketed as the **Mega 2560 PRO Mini**) is a compact, embedded-oriented variant of the classic Arduino Mega 2560. It packs the same ATmega2560-16AU microcontroller into a dramatically reduced footprint — typically **38 × 52 mm** — making it ideal for permanent installations, solder-proto-board projects, and battery-powered applications where the full-size Mega's bulk is impractical.

Unlike the standard Arduino Mega 2560 R3, the Mega Mini **omits the onboard USB-to-serial controller**. This is not a limitation but a deliberate design choice: the board is programmed via an external USB-TTL adapter, which keeps the PCB smaller, reduces idle current draw, and lowers cost. Once programmed, the external adapter is no longer needed, making the board well-suited for embedded deployments.

The board is functionally identical to the Arduino Mega 2560 in terms of I/O count, memory, and clock speed. If your project outgrows an Uno but you don't have room for a full Mega, the Mega Mini is the natural next step.

> **Note on naming:** You will see this board sold under several names: *Mega 2560 PRO Mini*, *Mega 2560 Pro Mini*, *Arduino Mega 2560 PRO MINI*, and *Meduino*. They all refer to the same form factor and chipset. Be aware that some vendors sell a variant **with** an onboard CH340G USB chip (the "PRO Embed" version, 38 × 55 mm), while the true PRO Mini has **no** USB controller.

## Pinout

The Mega Mini uses the **same pin mapping as the Arduino Mega 2560**. Every digital pin, analog pin, UART, SPI, and I²C line maps identically to the ATmega2560's physical pins. This means any shield or library written for the Mega 2560 will work without modification — provided the physical form factor permits it (the Mega Mini does not accept standard Arduino shields due to its compact layout).

### Digital Pins (D0–D53)

- **D0 (RX0) and D1 (TX0):** Hardware serial 0. These are reserved for USB-serial communication when using the bootloader. If you need a free serial port for peripherals, use Serial1, Serial2, or Serial3.
- **D2–D13:** Standard digital I/O. Pins D2–D13 support PWM (some with caveats — see the full mapping).
- **D14–D19:** Digital I/O (no PWM).
- **D20 (SDA) and D21 (SCL):** Hardware I²C. Pull-up resistors are not onboard; add external 4.7 kΩ pull-ups when using I²C devices.
- **D22–D53:** Extended digital I/O, including the SPI bus (D50 = MISO, D51 = MOSI, D52 = SCK, D53 = SS).

### Analog Inputs (A0–A15)

All 16 analog inputs provide 10-bit resolution (0–1023). Pins A0–A15 correspond to ADC0–ADC15 on the ATmega2560. They can also be used as digital I/O pins (A0–A15 map to digital pins 54–69 in the Arduino numbering scheme).

### PWM Outputs

The Mega 2560 provides **15 PWM channels**. On the Mega Mini, these are available on the same pins as the full-size Mega. PWM is generated by the ATmega2560's Timer/Counter peripherals. The following pins support PWM: D2–D13, D44, D45, D46.

### Communication Interfaces

| Interface | Pins | Notes |
|---|---|---|
| Serial 0 (USB-serial) | D0 (RX0), D1 (TX0) | Used by bootloader |
| Serial 1 | D18 (TX1), D19 (RX1) | Free for peripherals |
| Serial 2 | D16 (TX2), D17 (RX2) | Free for peripherals |
| Serial 3 | D14 (TX3), D15 (RX3) | Free for peripherals |
| I²C (TWI) | D20 (SDA), D21 (SCL) | External pull-ups required |
| SPI | D50 (MISO), D51 (MOSI), D52 (SCK), D53 (SS) | Also on ICSP header |

### ICSP Header

A 6-pin ICSP (In-Circuit Serial Programming) header is present on the board edge. This allows you to bypass the bootloader entirely and program the ATmega2560 directly using an external programmer (AVR ISP, USBasp, etc.). This is useful for recovering a corrupted bootloader or for production flashing where the bootloader overhead is undesirable.

### FTDI / USB-TTL Header

On the PRO Mini version (no onboard USB), programming is done through a dedicated FTDI header. The pinout is:

| FTDI Adapter | Mega 2560 PRO Mini |
|---|---|
| TX | RX0 |
| RX | TX0 |
| DTR | DTR (auto-reset) |
| GND | GND |
| VCC (5 V) | VCC |

The **DTR line** is connected to the reset circuit via a capacitor. When the Arduino IDE initiates an upload, the DTR signal pulses, resetting the ATmega2560 and allowing the bootloader to run. This enables **auto-reset** during programming, just like a standard Arduino.

## Programming

### Using the Arduino IDE

The Mega Mini is programmed exactly like an Arduino Mega 2560. No special board definition is required for most use cases.

1. **Install the Arduino IDE** (version 1.8.x or 2.x).
2. **Connect the board** via a USB-TTL adapter (FTDI, CH340G, CP2102, or similar) to the FTDI header.
3. **Select the board:** `Tools → Board → Arduino Mega or Mega 2560`.
4. **Select the processor:** `ATmega2560 (Mega 2560)`.
5. **Select the port** corresponding to your USB-TTL adapter.
6. **Upload** your sketch as normal. The bootloader auto-resets via the DTR line.

> **CH340 driver note:** If you are using a CH340G-based USB-TTL adapter, you may need to install the CH340 driver on your operating system. Windows 10 and later often install it automatically; macOS and Linux users may need to install it manually.

### Custom Board Definition (Optional)

In some cases, you may want to add a custom board entry to the Arduino IDE to reflect the Mega Mini's specific variant. The GitHub repository `semaf/Mega2560ProMini` provides a `pins_arduino.h` file and a `boards-atmega2560.txt` file for this purpose. The general procedure is:

1. Locate your Arduino installation's `hardware/arduino/avr/variants` folder.
2. Create a new folder (e.g., `mega2560promini`) and place the `pins_arduino.h` file inside.
3. Append the contents of `boards-atmega2560.txt` to `boards.txt` in the `hardware/arduino/avr/` folder.
4. Restart the Arduino IDE. The new board should appear in the Tools → Board menu.

For most users, however, selecting the standard "Arduino Mega 2560" board is sufficient — the pin mappings are identical.

### Bypassing the Bootloader (ICSP)

If you need to program the board without the bootloader — for faster startup, more flash space, or recovery from a corrupted bootloader — use the ICSP header with an external programmer. The standard `avrdude` command for flashing a bootloader to the ATmega2560 is:

```bash
avrdude -cavrispv2 -patmega2560 -P/dev/ttyACM0 -b115200 -e -u \
  -U lock:w:0x3F:m -U efuse:w:0xFD:m -U hfuse:w:0xD8:m -U lfuse:w:0xFF:m
avrdude -cavrispv2 -patmega2560 -P/dev/ttyACM0 -b115200 \
  -U flash:w:stk500boot_v2_mega2560.hex
avrdude -cavrispv2 -patmega2560 -P/dev/ttyACM0 -b115200 -U lock:w:0x0F:m
```

This flashes the STK500v2 bootloader, which is the standard bootloader for the Arduino Mega 2560. To flash an application directly (bypassing the bootloader entirely), use:

```bash
avrdude -cwiring -patmega2560 -P/dev/ttyACM0 -b115200 -D \
  -U flash:w:your_sketch.hex:i
```

> **Caution:** When flashing a bootloader via ICSP, the `-e` flag erases the chip, including any existing bootloader. Ensure you have the correct bootloader hex file before proceeding.

## Bootloader

The ATmega2560 on the Mega Mini comes pre-burned with a bootloader that allows you to upload new code without an external hardware programmer. The standard bootloader is **STK500v2** (sometimes called `stk500boot_v2_mega2560.hex`), which is the same bootloader used on the official Arduino Mega 2560.

### Bootloader Behavior

- On power-up or reset, the bootloader runs for a brief window (typically ~1–2 seconds).
- If it receives a valid upload command from the Arduino IDE, it writes the new sketch to flash.
- If no upload command is received, it jumps to the existing application in flash.
- The bootloader occupies **8 KB** of flash memory, leaving 248 KB for your sketches.

### Recovering a Corrupted Bootloader

If the bootloader becomes corrupted (e.g., due to a failed upload or accidental ICSP flash), you can restore it using an external programmer and the `avrdude` commands shown above. The bootloader hex file is available in the Arduino IDE installation directory under `hardware/arduino/avr/bootloaders/stk500v2/`.

## Power Supply

The Mega Mini can be powered through several methods:

1. **FTDI header VCC pin:** Supply regulated 5 V directly to the VCC pin. This is the most common method during development.
2. **External power pins:** The board has dedicated VIN and GND pins for connecting an external power supply (6–12 V recommended).
3. **Micro USB / Type-C (PRO Embed variant):** If you have the PRO Embed version with an onboard CH340G, you can power the board through the USB connector.

The onboard voltage regulator (LDO) can handle input voltages from **6 V to 9 V** (peak 18 V) DC. The output current is approximately **800 mA on the 5 V rail** and **800 mA on the 3.3 V rail**. Note that the higher the input voltage, the lower the available output current due to thermal dissipation.

### Power Considerations

- The ATmega2560 itself draws relatively little current (~20–30 mA at 16 MHz, 5 V), but the 5 V rail must also power any shields or peripherals you connect.
- If you are powering the board from a battery, the absence of an onboard USB controller means idle current is lower than a standard Mega 2560. This is one of the key advantages of the PRO Mini design.
- The 3.3 V rail is derived from the 5 V rail via an onboard LDO. If you need significant current at 3.3 V, consider an external regulator.

## Differences from the Standard Arduino Mega 2560

| Feature | Arduino Mega 2560 R3 | Mega 2560 PRO Mini |
|---|---|---|
| Dimensions | 101 × 53 mm | 38 × 52 mm |
| USB Interface | ATmega16U2 (USB-B) | None (external FTDI) |
| Shield Compatibility | Yes (R3 footprint) | No (compact layout) |
| Programming | USB-B cable | USB-TTL adapter |
| Idle Power | Higher (USB controller active) | Lower |
| Cost | Higher | Lower |
| Ideal For | Education, shield prototyping | Embedded, permanent installations |

The classic Mega 2560 R3 uses an **ATmega16U2** as its USB-to-serial converter, which can be reflashed to emulate HID devices (keyboard, mouse, MIDI). The PRO Mini has no such chip, so HID emulation is not possible without additional hardware.

The PRO Mini is **~63% smaller** than the classic Mega 2560, making it dramatically more suitable for projects where space is at a premium.

## Common Use Cases

- **3D printer control boards:** The ATmega2560 is the standard controller for many RepRap-style 3D printers. The Mega Mini is often used in custom printer builds where space inside the enclosure is limited.
- **Embedded installations:** Once programmed, the Mega Mini can be soldered directly onto a protoboard or PCB, with no need for a USB connector.
- **Battery-powered projects:** The absence of a USB controller reduces idle current draw, extending battery life.
- **Multi-sensor data acquisition:** With 54 digital I/O, 16 analog inputs, and 4 hardware UARTs, the Mega Mini can interface with a large number of sensors and peripherals simultaneously.
- **Porting projects from other platforms:** As demonstrated by the W8BH Morse Tutor port, code originally written for other microcontrollers can be adapted to the Mega Mini with pin reassignments.

## Troubleshooting

**Board not detected by computer.**
- Ensure the USB-TTL adapter's TX connects to the board's RX, and RX connects to TX. This is a common wiring mistake.
- Check that the CH340 or FTDI driver is installed.
- Verify the adapter is supplying 5 V to the VCC pin.

**Upload fails with "avrdude: stk500_recv(): programmer is not responding."**
- Ensure you have selected the correct board (`Arduino Mega 2560`) and processor (`ATmega2560`).
- Press the reset button on the board just before the IDE begins uploading. The DTR auto-reset may not work with all USB-TTL adapters.
- If auto-reset persistently fails, manually press the reset button when the IDE shows "Uploading…" in the status bar.

**Board resets unexpectedly during operation.**
- Check the power supply. The 5 V rail may be sagging under load. The onboard LDO can supply ~800 mA, but if your peripherals draw more, the voltage may drop and trigger a brownout reset.
- Ensure the reset pin is not floating. A 10 kΩ pull-up to VCC is recommended if the reset line is exposed.

**Bootloader appears corrupted.**
- Re-flash the bootloader via the ICSP header using the `avrdude` commands above.
- If you do not have an external programmer, you can use another Arduino (e.g., an Uno) as an ISP programmer to restore the bootloader.

**Sketch uploads but does not run.**
- Verify that the bootloader is not stuck in an infinite loop. Try a simple Blink sketch to confirm basic functionality.
- Check for pin conflicts. Pins D0 and D1 are used by the serial bootloader; if your sketch uses them for other purposes, the upload process may interfere.
