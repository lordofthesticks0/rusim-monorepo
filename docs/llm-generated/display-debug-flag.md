# Display `IS_DEBUG` flag

`IS_DEBUG` is the compile-time gate for debug-only shortcuts in the
`display-v9` UI. It defaults to off and is enabled per build with a
`-D` flag. It is intentionally general: future debug shortcuts should
branch on it rather than adding a new flag each time.

## Definition

`firmware/display-v9/ui_config.h`:

```c
#ifndef IS_DEBUG
#define IS_DEBUG 0
#endif
```

Because it is guarded by `#ifndef`, a `-DIS_DEBUG=1` build flag overrides
the hardcoded default without editing the source.

## Enabling it

Uncomment the line in `[env:display-v9]` in `platformio.ini`:

```
; -DIS_DEBUG=1
```

`[env:display-sim]` inherits `display-v9` build flags, so the same
uncomment enables it in the simulator. For a one-off build without
editing the file:

```bash
PLATFORMIO_BUILD_FLAGS="-DIS_DEBUG=1" pio run -e display-sim
```

Both states compile: `pio run -e display-sim` was verified with the
flag off (default) and with `-DIS_DEBUG=1`.

## Current effects

| Flag | Behaviour |
|---|---|
| `0` (default) | No change. All debug UI compiles out. |
| `1` | `/setup` (the login screen) shows an extra `DEBUG: bypass login` button (`firmware/display-v9/screen_setup.cpp`). Tapping it runs the normal success path (`setup_close_success()`): sets `g.loggedIn`, stops the credential SoftAP, and routes to `/home` without waiting for the WT32 `RESULT=success`. |

The boot still starts at the login screen in both modes; the flag only
adds a way past it. Later `LOGIN_REQ` frames from the WT32 still route
back to `/setup`, where the button is available again.

## Rules for new uses

- Guard with `#if IS_DEBUG`, so release builds (`0`) contain none of the
  debug code.
- Keep debug widgets visibly marked (`DEBUG:` prefix, warning colour).
- Never enable in a production flash: the bypass skips portal
  authentication.
