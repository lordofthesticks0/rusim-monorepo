# Display LVGL 9.3.0 -> 9.6.0 port

Pinned `firmware/display-v9` to LVGL 9.6.0 (was 9.3.0) in `platformio.ini`
(both `display-v9` and `display-sim` envs). Verified version in
`.pio/libdeps/display-sim/lvgl/include/lvgl/lv_version.h`
(9.6.0). Both `display-sim` (native/SDL) and `display-v9` (ESP32-S3)
build with zero warnings.

## Config (`lv_conf.h` + `sim/lv_conf.h`)

- `LV_COLOR_DEPTH` replaced with `LV_COLOR_FORMAT_DEFAULT`
  (`RGB565` on device, `XRGB8888` in the sim). `LV_COLOR_DEPTH` is
  derived/read-only in 9.6.
- Removed deprecated `LV_MEM_POOL_EXPAND_SIZE` (warns in 9.6;
  `LV_MEM_SIZE = 64*1024` bytes already covers it).
- Removed deprecated `LV_ASSERT_HANDLER_INCLUDE`; kept
  `LV_ASSERT_HANDLER while(1)`.
- Sim only: enabled `LV_USE_LOG` + `LV_LOG_PRINTF` so failed
  `LV_USE_CHECK_ARG` checks (on by default in 9.6) are visible
  instead of failing silently.

## Code (9.6-clean, proven with `-DLV_DISABLE_API_MAPPING`)

- `lv_obj_add/remove/clear_flag(..., LV_OBJ_FLAG_HIDDEN)` ->
  `lv_obj_set_hidden(o, true/false)` (`screen_setup.cpp`,
  `screen_info.cpp`).
- `lv_obj_remove_flag(..., LV_OBJ_FLAG_SCROLLABLE)` ->
  `lv_obj_set_scrollable(o, false)` (`ui_shell.cpp`).
- `lv_obj_{has,add,remove}_state(..., LV_STATE_CHECKED)` ->
  `lv_obj_is_checked` / `lv_obj_set_checked(o, bool)`
  (`screen_control.cpp`).
- `lv_timer_del` -> `lv_timer_delete`, `lv_obj_del` -> `lv_obj_delete`.
- `lv_chart_set_range` -> `lv_chart_set_axis_range`
  (`screen_data.cpp`); `LV_LABEL_LONG_WRAP` ->
  `LV_LABEL_LONG_MODE_WRAP` (`ui_shell.cpp`). Both found only by the
  `LV_DISABLE_API_MAPPING` build; they compiled silently via compat
  aliases otherwise.
- Added missing `#include <ctype.h>` in `serial_cmd.cpp` (`toupper`
  was previously pulled in transitively by LVGL headers).
- Bumped `FW_VERSION` to `v9.6-fake-0.2.0` so the port is visible on
  `/info`.

## Deliberately not changed

- `#include <lvgl.h>` kept instead of the skill-preferred
  `<lvgl/lvgl.h>`: PlatformIO exposes the library root on the include
  path, so the nested path does not resolve. The root header is still
  supported in 9.6 (only `src/` private includes are deprecated).
- QR code flow untouched: `lv_qrcode_set_size` is called before
  `lv_qrcode_update`, so the 9.6 re-encode behavior does not add cost.
- `LV_USE_SDL` block untouched: `LV_SDL_BUF_COUNT` form already
  matches 9.6; no backend macros needed for this sim.
