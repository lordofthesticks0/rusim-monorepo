# MH-Z19C PWM Pin Readout (D4-D7)

Sketch: `firmware/tests/pwm-pins-readout/main.cpp`. PlatformIO environment: `pwm-pins-readout` (Mega 2560).

Prints a JSON sample of the PWM signals on **D4-D7** once every 2 s. The board has faulty PWM pins, so only these four are sampled. UART is not used.

## Wiring

| Sensor pin | Mega pin |
|---|---|
| PWM | any of D4-D7 |

Vin to 5V, GND to GND. Tx, Rx, HD and Vo are not connected.

The sketch samples all four pins, so moving the PWM wire between D4 and D7 needs no firmware change.

## Run

```bash
pio run -e pwm-pins-readout -t upload
pio device monitor -b 115200
```

To keep a log, redirect the monitor output. Every line is a complete JSON object, so the file is JSON Lines:

```bash
pio device monitor -b 115200 | tee pwm-log.jsonl
```

The sketch prints no banner or status text, so nothing breaks a JSON parser. Wait about 1 minute after power-on for the sensor to preheat before trusting the ppm values.

## Output

One line per sample (wrapped here for readability, not wrapped on the wire):

```json
{"uptime_ms":12000,"range_ppm":5000,"pins":[{"pin":4,"signal":true,"high_ms":123.4,"period_ms":1004.0,"duty_pct":12.3,"ppm":607},{"pin":5,"signal":false,"high_ms":null,"period_ms":null,"duty_pct":null,"ppm":null},{"pin":6,"signal":false,"high_ms":null,"period_ms":null,"duty_pct":null,"ppm":null},{"pin":7,"signal":false,"high_ms":null,"period_ms":null,"duty_pct":null,"ppm":null}]}
```

| Field | Meaning |
|---|---|
| `uptime_ms` | `millis()` at the time of the sample |
| `range_ppm` | 5000, the range used by the ppm math |
| `pins[]` | one object per pin, in order D4-D7 |
| `pin` | Arduino pin number (4-7) |
| `signal` | `true` when a plausible cycle was measured in the last 3 s |
| `high_ms` | `Th`, the HIGH time of the last complete cycle |
| `period_ms` | rise-to-rise time, about 1004 ms |
| `duty_pct` | `high_ms / period_ms`, in percent |
| `ppm` | decoded concentration, assuming the 5000 ppm range |

With `"signal":false`, every measurement field is `null`. A missing signal is not reported as zero, so averages computed from the log stay meaningful.

## How it measures

D4-D7 have no hardware external interrupts on the Mega 2560 (only D2, D3 and D18-D21 do). Rather than mixing `attachInterrupt()` with polling, the sketch polls all four pins the same way:

1. `loop()` calls `sampleAll()`, which reads each pin with `digitalRead()` and timestamps transitions with `micros()`. A sweep over four pins takes roughly 20-30 us.
2. A rising edge starts a cycle. The next rising edge gives the period; the falling edge after a rise gives `Th`.
3. When the falling edge closes a cycle, `Th` and the period of that same cycle are latched as the pin's current reading, but only if the pair is plausible (period 950-1060 ms, `2 ms < Th < period`). A missed edge produces an implausible pair and is discarded.
4. The latched reading is printed for up to 3 s. After that the pin reports `"signal":false`.

The shortest MH-Z19C pulse is 2 ms, so a sweep of a few tens of microseconds is accurate to well under 0.1 ms. Printing takes a few tens of milliseconds per burst, so an occasional cycle is dropped; the pin keeps its last reading and only reports no signal after 3 s without a plausible cycle.

All timing math is integer:

```
ppm = Range * (Th - 2 ms) / (Th + Tl - 4 ms)
```

`Th` and the `(Th + Tl - 4 ms)` window are converted to 0.1 ms units so `Range * numerator` fits in 32 bits. JSON numbers are printed as integer part plus one decimal, never as floats. No `String`, no dynamic allocation, no input parsing.

## Range

`kRangePpm` is set to 5000, the sensor's default. Change it to 2000 or 10000 in the sketch if the sensor was configured differently. Without UART the sketch cannot read or change the range on the sensor.

The period is 1004 ms at any range; only the ppm scaling changes. A wrong `kRangePpm` scales every reading by a constant factor (5000 instead of 2000 reads 2.5x low).

## Troubleshooting

**Every pin reports `"signal":false`**

Check sensor power (5 V), ground, and that the PWM wire is seated. Run the sketch again after the 1 minute preheat.

**One pin reports a signal, the others do not**

That pin is connected to the sensor's PWM output. This is the expected result.

**A pin flickers between a reading and `"signal":false`**

Normal when an edge falls inside a print burst. It does not indicate a wiring fault.

**Reading is exactly 5000 ppm with duty near 100%**

The sensor is at full scale: usually preheating or in a fault state, not a real measurement.

## Safety

The sketch only reads pins and writes to USB serial. It never drives a sensor pin or changes sensor settings.

The MH-Z19C range tops out at 5000 ppm (10000 optional). Rumen headspace (about 700,000 ppm CO2) is far outside it. See `docs/hardware.md` §5.3.
