# DB experiment sync + NTP — LLM Documentation

Backlog #1 (real DB fetch), #9 (experiment number from DB latest+1 with mismatch warn), #12 (NTP sync).

## Auth used

Reuses `device_data.authenticate(p_token)` (`dashboard/supabase/migrations/20260930162000_add_device_data_token_auth.sql`). No schema change. RLS scopes reads to the session device, so the firmware sends no `device_id` filter.

## Master (`firmware/network-master/main.cpp`)

Build flags, never committed: `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `DEVICE_TOKEN`, optional `RUSIM_DEVICE_ID` (default 0, log only; RLS selects the device).

Flow:
- `ensureNtpSync()` after DHCP: `configTime(0, 0, "pool.ntp.org", "time.google.com")`, waits 10 s for `time() > 1700000000`. Sets `LINK_REG_TIME_OK`.
- `sbAuthenticate()`: `POST <url>/rest/v1/rpc/authenticate` with `{"p_token":...}`, extracts the 64-hex `session_token` into RAM.
- `sbFetchLatestExp()`: `GET <url>/rest/v1/readings?select=experiment_id&order=experiment_id.desc&limit=1` with `apikey` + `x-device-session`. Returns latest id, `-1` when empty, `-2` on failure. Re-auths once on 401/403.
- `syncDbLatest()` every 30 s in NEED_CREDS and RUN, forced once after LOGIN. `pushDbState()` writes `LINK_REG_DB_LATEST` (`0xFFFF` = unknown, else id; `-1` none reports 0) and `TIME_OK`.

Portal verdict still uses the lyrics `fetchData()`; Supabase fetch is the real-data path.

## Link (`link_modbus.h`)

- `0x0005 DB_LATEST`, master WR, slave RO. `0xFFFF` unknown.
- `0x0006 TIME_OK`, master WR, slave RO. 1 = NTP synced.

## Display (`firmware/display-v9/`)

- `link_modbus.cpp`: stores `s_dbLatest` (`-2` unknown, `-1` none) and `s_timeOk`; readable via `link_modbus_get_db_latest()` / `link_modbus_time_ok()`.
- `screen_control.cpp`: `s_dbWarn` label replaces the static note. `db_refresh_warn()` auto-sets the spinbox to `latest+1` once per boot, then shows `WARN: exp N already in DB (latest M)` when `local <= latest`, else `DB latest M, next M+1 OK`. `screen_control_poll()` (called from `main.cpp` loop) applies late syncs to the open screen.
- `screen_info.cpp`: shows `DB latest exp` row with NTP state.

## Build

```
pio run -e network-master -- -DSUPABASE_URL='"https://xyz.supabase.co"' -DSUPABASE_ANON_KEY='"..."' -DDEVICE_TOKEN='"..."'
```

Without flags the DB sync logs `Supabase not configured` and the display shows `waiting for master sync`; portal + Modbus experiment polling still work.
