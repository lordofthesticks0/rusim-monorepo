# Legacy Master USB Tool (`scripts-hardware/legacy-master-usb.ts`)

## 1. Purpose

[`scripts-hardware/legacy-master-usb.ts`](../../scripts-hardware/legacy-master-usb.ts) is a Bun interactive REPL that talks to the legacy water-bath master (`legacy/master/master.cpp`) directly over USB serial. It replaces the Raspberry Pi Flask backend (`legacy/pi/water-control-system/web_control.py`) for bench work: any computer with Bun and PlatformIO can send commands and read telemetry without the Pi.

## 2. Wire protocol

The master uses `Serial` (UART0, D0/D1) at 115200 baud, newline-terminated ASCII. See [legacy-master.md](legacy-master.md) §8 for the full command list.

Commands accepted:

- `STATUS` → one `{"type":"master_status", ...}` JSON line.
- `MODE_AUTO` / `MODE_OFF`
- `HEATER_AUTO` / `HEATER_ON` / `HEATER_OFF`
- `PUMP_AUTO` / `PUMP_ON` / `PUMP_OFF`, plus `PUMP1_*` / `PUMP2_*`
- `PWM:<D3|D7|D4>:<0-255>` (aliases `PUMP1`/`PUMP2`/`STIR` also accepted by the firmware)
- `STIR:<mode 0-3>:<mins>:<secs>`
- `TEMP:<target 20-50>:<hysteresis 0.1-5>`

The master also forwards every slave packet from `Serial1` (9600 baud) to USB as a `{"bottles":[...]}` JSON line. The tool prints both streams: `master_status` as a one-line summary (bath/avg temps, mode, heater/pump/stirrer states, water level, PWM ceilings vs outputs) and `bottles` as a per-bottle table. `--json` prints raw lines instead.

## 3. How it opens the port

- Autodetect uses `pio device list --json-output`, drops `/dev/ttyS*` entries, prefers ports with a real `hwid`. `--port` overrides; `--list-ports` prints candidates and exits.
- Linux/macOS: `stty` sets raw 8N1, `clocal`, no echo, no hangup control. Windows: `stty` is skipped (no equivalent); the COM port is opened with defaults.
- Opening the port pulses DTR and resets the Mega. The tool discards telemetry for `--settle` seconds (default 5) after the first bytes arrive, then resyncs to the next newline so the first printed line is complete. This matches `read-legacy-slave.ts`.
- Incoming bytes are split on newlines and held for 100 ms of silence before parsing (`FRAME_QUIET_MS`), so a JSON frame split across serial chunks is printed whole.

## 4. REPL behaviour

- Prompt is `master> `. Anything typed is sent to the master with a trailing newline, except local commands `help`, `exit`, `quit`, `clear`.
- `--cmd <command>` sends one command, waits 1.5 s for the reply, then exits. Useful for scripts and tests.
- `Ctrl+C` / `Ctrl+D` exits. Serial read/write errors print a hint to close other monitors and exit non-zero.

## 5. Usage

```bash
bun scripts-hardware/legacy-master-usb.ts
bun scripts-hardware/legacy-master-usb.ts --port /dev/ttyUSB0
bun scripts-hardware/legacy-master-usb.ts --json
bun scripts-hardware/legacy-master-usb.ts --cmd STATUS
bun scripts-hardware/legacy-master-usb.ts --list-ports
```

## 6. Limits

- The tool does not send `BOOT_DEFAULT_COMMANDS` (`HEATER_OFF`, `PUMP1_OFF`, `PUMP2_OFF`, `STIR:0:10:30`). The Pi sends those once on first connect; this tool leaves the master's boot defaults untouched. Send them manually if you need a known state.
- Windows COM ports depend on Bun/Node `fs` support for the device path. If `createReadStream` fails on a COM port, use `--port` with the exact `COMn` name from `pio device list` and check that no other process holds the port.
- Only one process can hold the port. Close `pio device monitor`, Arduino Serial Monitor, or the Pi `water-ui` service before opening it here.
